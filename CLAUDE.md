# racecraft — правила работы

Проект ведут двое (@levalovushka и @dmitrynishchev), асинхронно, часто через Claude. Описание проекта — в [README.md](README.md).

## Git
- Никогда не пушить в `main` напрямую и не делать force push в `main`. `main` сразу уходит на сайт через Netlify.
- Одна задача — одна ветка от свежего `main`: `git switch main && git pull && git switch -c <тип>/<коротко>` (`feat/`, `fix/`, `docs/`, `chore/`).
- Готово → push ветки и pull request в `main`. Сливает автор после зелёной проверки CI, способ — squash merge.
- PR маленькие и короткоживущие (1–2 дня). Длинная работа — регулярно подтягивать `main` в ветку (`git merge origin/main`).
- Конфликт при слиянии с чужими изменениями — не выбирать «свою версию» вслепую: разобраться, что поменял второй, сохранить оба смысла; если неясно — спросить в PR.
- Не переписывать историю уже запушенных веток, в которых может работать второй человек.

## Перед PR
`cd sim && npm run lint && npm run build` — должно проходить. Это же проверяет CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)).

## Секреты
Репозиторий публичный: никаких токенов, паролей и ключей в коде и коммитах. Данные заездов (`data/`) в git не попадают.
